# 设计：审计驱动的 Git 文档来源（可修改、可回撤）

> 状态：**设计定稿，未实施**（2026-10 与需求方讨论定案）。本文记录方案取舍与实施拆分，
> 实施时按"实施拆分"逐项落地并回填状态。

## 背景与需求

数据源是一个 git 仓库：所有操作通过 **PR 触发**，PR 统一审核合入后自动整理经验文档落到
一个输出路径上；后期发现问题的修改/删除同样走 PR。KB 需要消费该路径，且满足对方审计要求：

- **可修改**：文章改版重新输出 → KB 更新内容，身份不变，人工标签/遥测跟随；
- **可回撤**：文章被撤稿（PR 删除文件）→ KB 自动删除该文档，**不复活**，且**保留痕迹**；
- 改名/移动 = 删旧增新（已确认可接受——文件名即身份，`source_id = md:<stem>`）；
- 手动清输出目录属删库级事故，从管理侧约束，不在导入层兜底（见"后置 TODO"）。

## 与现有机制的映射

| 需求 | 现有机制 | 结论 |
|---|---|---|
| 可修改 | upsert 同 sid 内容变化 → 重切分/重嵌入，身份不变；doc_verification 内容指纹使旧认证自动失效、回审核队列重审 | **零开发**，直接受益 |
| 可回撤（删除） | `mark_deleted` 链路（备份 doc_row → 四层删 → 墓碑 → 待实际删除可撤回）已是安全可逆的一等删除，但只能人工触发 | **缺口**：需要"跟随源自动删除" |
| 不复活 | 删除墓碑（`deleted_docs`）在 ingest / canonical upsert / build_graph 三处拦截 | **零开发**，mirror 模式删除即走墓碑 |
| 队列自愈 | seed sweep：悬空 tag_candidate / verification_pending 自动忽略 | **零开发**，撤稿后队列自动干净 |
| 痕迹保留 | 墓碑表（source_id/deleted_at/reviewer）+ 待实际删除审核项 | 缺一个**查询视图**（实施拆分 #4） |

## 方案定案

**按来源可配置的删除策略**（不对全局语义做任何改动，其他来源零影响）：

```jsonc
// config.json 来源条目新增字段（缺省 keep，现状语义）
{"name": "audited_docs", "path": "data/imports/audited", "deletion_policy": "mirror"}
```

- **`keep`（默认，= 现有"增量"机制）**：发现层只增改，不删；文件消失 = 静默偏离 +
  stray 告警，中间数据不修改——适用于一切不可信路径；
- **`mirror`（本地原始数据优先）**：该路径是**唯一事实源**，对账删除触发墓碑机制——
  适用于审计驱动的可信路径（本需求）。

### mirror 模式对账内核

每次构建（增量与 `--rebuild` 同路径）：

1. 发现该来源文件 → 计算内容 sha256；
2. 与上次快照（`data/source_state/<source>.json`，`{source_id: sha256}`）diff：
   - **新增/内容变化** → 走现有 upsert 入库（无需对账层干预）；
   - **缺席** → **宽限期计数**（快照记 `absent_count`）：**连续 2 次构建缺席才真删**
     ——挡 git checkout/切分支/同步中断等瞬态；
3. 达到宽限 → 自动执行 `mark_deleted` 链路：备份 doc_row → 删 kb 四层 → **登记墓碑** →
   生成"待实际删除"审核项（note 标注"来源回撤自动删除"）——**撤稿本身可撤**
   （待实际删除列表一键恢复，墓碑同步解除）；
4. 构建日志打印对账清单：`[audited_docs] 新增 X · 更新 Y · 回撤 Z（宽限中 W）`，
   与对方 PR 合入记录可对账。

### 语义细节

- **改名/移动**：旧 sid 走回撤删除（墓碑），新 sid 全新入库——人工标签不跟随
  （已确认接受；如需迁移标签，撤稿前人工操作）；
- **版本回退**（revert 到旧内容）：sha 等于旧值 → upsert 写回旧内容；内容指纹不符 →
  人工认证自动失效 → 回队列重审（与对方审计改版对齐：**对方改版，我方重审**）；
- **快照文件损坏/丢失**：视为首轮——只建快照不删除（宁漏删不误删），日志告警；
- **痕迹**：墓碑表天然记录 `who/when`；审核台提供"已回撤"视图（见拆分 #4）；
  恢复 = 待实际删除撤回。
