requests>=2.28

jieba>=0.42             # 入库侧/查询侧分词（scripts/build_fts.py 重建全文索引，不重嵌向量）

# ---- OCR 第二意见复核（可选——默认不装；主 OCR 是外部 API，与此包无关）----
# paddleocr>=3.7         # ① 本地 OCR 主引擎（ocr_provider=paddle 可选模式）；② PP-OCR 第二意见复核
# paddlepaddle>=3.0      # CPU 版 wheel 即可——与 ascend NPU 无关，不装 NPU 插件就不碰卡。
#                        # 注意 wheel 按平台发布：x86_64 上限 3.3.1；**aarch64（鲲鹏/昇腾容器）PyPI 上限 3.2.2**——
#                        # 3.2.2 与 paddleocr 3.7 兼容（paddleocr 只要求 paddlepaddle>=3.0），直接装即可
# 业务环境（openEuler + ascend）默认不装：三方框架在 NPU 上的兼容性不做保证，且复核是
# 增强能力——不装则三档分流退化为现状（低置信直进人工审核，队列与主链路完全不受影响）。
# 系统运行库（Linux）：libstdc++/libgomp 通常已预装；opencv 缺 libGL 时 dnf install
# mesa-libGL（或 pip 装 opencv-contrib-python-headless 替代——注意先卸 opencv-contrib-python
# 完整版避免并存冲突）。Windows 另需 VC++ Redist 2015-2022 x64。
# 开关：image 源 ocr_second_opinion（默认 true）——装了即启用复核，false 单独关闭；
# 权重默认 ~/.paddlex/official_models/（约 23MB），PADDLE_PDX_CACHE_HOME 可重定向；
# **离线/内网环境加 PADDLE_PDX_DISABLE_MODEL_SOURCE_CHECK=True**（paddlex 启动时会做
# 模型源联网检查，离线机器卡超时；主进程环境设置即可，runner 子进程继承）。
# **vllm-ascend 共享 venv 场景**：勿在主 venv 装/换 opencv（headless 替换会破坏 vllm-ascend
# 依赖链）——paddle 装独立 venv 或 pip --target 隔离目录，image 源配 ocr_pp_python
# （独立解释器）+ ocr_pp_pythonpath（--target 目录），子进程长驻隔离，主 venv 零改动。
# **⚠️ 容器系统 Python 裸装 paddle 会把 numpy 降级到 1.26.x**（aarch64 paddlepaddle 3.2.x
# 依赖链 pin numpy<2，而主链路 pyarrow/lancedb 要求 numpy≥2.0 → lancedb 无法加载、检索
# 全挂）——PYTHONPATH 也绝不能 shell 全局 export（遮蔽主进程 numpy）；PYTHONPATH 只经
# config ocr_pp_pythonpath 注入 runner 子进程。恢复：pip install "numpy>=2.0,<2.4" --upgrade。
